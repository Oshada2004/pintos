#### ALGORITHMS

>A2: Briefly describe what happens in a call to timer_sleep(),
>including the effects of the timer interrupt handler.

In `timer_sleep()`:

1. Returns `ticks>0` immediately
2. Computes wakeup tick as `timer_ticks()+ticks`
3. disable interrupts to avoid race conditions with `timer_interrupt()`
4. Sets `wakeup_tick` of cuurent thread and inserts it into `sleep_list` which gets sorted respect to `wakeup_tick`
5. Invokes `thread_block()` to change thread state to `THREAD_BLOCKED` and triggers a context switch

In `timer_interrupt()`:

1. `ticks` is incremented.
2. Inspects `sleep_list` starting from the front
3. For each thread whose `wakeup_tick<=ticks`, it removes the thread from `sleep_list`, calls `thread_unblock()` and places it on `ready_list`
4. Because the list is kept sorted it gets the first thread whose `wakeup_tick>ticks`

>A3: What steps are taken to minimize the amount of time spent in
>the timer interrupt handler?

`sleep_list` is maintained in sorted order by `wakeup_tick` upon insert
So `timer_interrupt()` only checks threads until it finds one whose wakeup tick has not yet arrived and then terminates the loop
The cost of maintaining sorted order is shifted entirely out of the interrupt context and into the calling thread in `timer_sleep()`
